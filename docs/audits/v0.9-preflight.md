# CornerOps v0.9 Preflight

## Decision

**STOP before implementation. Merge PR #21 first.**

The controlled-actions layer depends directly on the v0.8.1 persistence, approval, audit, loopback-bind and fail-closed changes. Building executors while those contracts remain outside `main` would create an avoidable stacked release and make approval-state and rollback review harder.

This branch contains only this preflight artifact. It is temporarily stacked on PR #21 commit `6a23e28`; no v0.9 action registry, executor, API, UI or real side effect has been added.

## Risks before v0.9

1. Implementing before PR #21 merges would couple v0.9 review to an unmerged persistence base.
2. Approval lifecycle expansion must migrate existing persisted records without making approved payloads mutable.
3. GitHub issue creation is the only proposed external side effect and requires checksum, idempotency, explicit approval and all real-execution flags.
4. Local notes/tasks must use only CornerOps persistence and must never reuse business database repositories.
5. A second process is unsupported by `file_json`; v0.9 must retain the single-process beta limit.
6. Payment, order, lead and quote mutations, customer messages, deploys, workflow triggers, native tools and all other external actions remain forbidden.

## Implementation plan after merge

1. Rebase this audit-only branch onto the merged PR #21 `main` and rerun v0.8.1 QA.
2. Add the action types, registry and fail-closed policy for exactly three allowlisted actions.
3. Extend the existing approval service with checksum-protected lifecycle transitions; do not duplicate approval or audit services.
4. Add persistent idempotency before any handler can execute.
5. Implement GitHub issue drafts first, with real creation disabled by default.
6. Implement local internal note/task repositories isolated from business data.
7. Integrate proposals into agents, operator interfaces and Control Tower without enabling blocked actions.
8. Add credential-free demos, full tests, security documentation and a dedicated v0.9 PR.

## Gate to resume

Resume v0.9 implementation only when all are true:

- post-merge `main` CI is green
- this branch is rebased onto that `main`
- v0.8.1 persistence and local beta demos still pass
