## Baseline verification

## Risks and controls

1. Approval payloads are stored only after validation/sanitization and protected by SHA-256 checksum.
2. Every execution requires an identified operator, an approved lifecycle state, audit availability and idempotency.
3. File JSON remains single-process only; external actions fail closed if idempotency is unavailable.
4. GitHub issue creation is the only external side effect and all enabling flags default off.
5. Local notes/tasks use isolated CornerOps stores, never business repositories.
6. Payments, order/lead/quote mutations, external messages, deploys, workflows, native tools and ClawHub execution remain forbidden.

## Implementation plan

1. Add exactly three action definitions and fail-closed policy.
2. Extend existing approvals with checksum-protected execution lifecycle.
3. Persist idempotency and isolated local note/task records.
4. Add GitHub draft/controlled handler, API, CLI and agent proposals.
5. Expose v0.9 state in Control Tower, Approval Center and Audit Viewer.
6. Validate credential-free demos, complete test suites and security documentation.
